# 마블 룰렛 지그재그 통로와 회전봉 재설계

## 배경

현재 코스는 사각 범퍼와 10개의 회전봉을 갖추었지만, 실제 구슬이 이동하는 경로는 여전히 너비 26의 직선형 외곽 안에 머문다. 상단 회전봉 2개는 램프 출구와 멀어 충돌하지 않는 경우가 많고, y=68의 회전봉 5개는 양쪽 우회 공간이 남아 있다. 결승 회전봉은 시계 방향으로 돌아 구슬을 걸치게 하기보다 아래로 보내는 역할을 한다.

`lazygyu/roulette`의 첫 맵이 다른 느낌을 만드는 핵심은 장애물 수가 아니라 연속적으로 굴곡진 실제 이동 벽이다. 외곽 프레임은 직선으로 보이지만, 구슬은 안쪽에서 좌우로 번갈아 좁아지는 통로를 통과한다. 이번 변경은 이 통로 구조를 NotMe의 현재 코스에 맞게 재구성한다.

## 원인 분석

### 상단 회전봉

- 첫 램프는 중앙의 구슬을 오른쪽으로 보내지만 `spinner:upper-left`는 x=6.5에 있다.
- 두 번째 램프는 구슬을 왼쪽으로 보내지만 `spinner:upper-right`는 x=19에 있다.
- 즉, 두 회전봉 모두 램프가 만드는 주요 낙하 경로의 반대쪽에 있다.

### y=68 회전봉 행

- 현재 다섯 회전봉의 중심 간격은 5, 길이는 3.2이므로 막대 사이 공간은 1.8이다.
- 구슬 지름은 0.5이므로 사이 공간은 통과 가능해야 한다. 문제는 사이 공간이 아니라 행 양끝에 활성 이동 벽이 없어 구슬이 돌지 않고 우회할 수 있다는 점이다.
- 참고 맵의 첫 및 마지막 회전봉은 실제 이동 벽 밖까지 돌아 측면 우회를 막는다.

### 결승 회전봉

- Canvas 좌표에서 y가 아래로 커지므로 양수 각속도는 화면상 시계 방향이다.
- 현재 `+1.2`는 입구 쪽 막대를 아래로 이동시켜 구슬의 통과를 돕는다.
- 사용자가 원하는 동작은 참고 맵처럼 반시계 방향으로 구슬을 한 차례 걸친 뒤 틈이 열릴 때 통과시키는 것이다.
- 왼쪽 중심의 반시계 회전은 유지하되, 막대가 깔때기 위에서 구슬을 다시 밀어 올리지 않도록 중심은 입구선 y=126에 두고 길이는 3으로 제한한다.

## 목표

- 외곽 안전 프레임은 직선형으로 유지한다.
- 구슬이 실제로 이동하는 내부 벽은 상단부터 결승 진입 전까지 연속적으로 굴곡진다.
- 상단 회전봉 2개를 램프 출구의 필수 통과 지점에 둔다.
- y=68의 다섯 회전봉은 서로 겹쳐 가로 빈틈 없이 이어지며, 맨 양끝 회전봉이 내부 이동 벽 밖까지 돌아 측면 우회를 막는다.
- 결승 회전봉은 반시계 방향으로 회전하며 입구에서 눈에 보이는 일시 정체를 만든다.
- 그러면서도 대표 100구슬이 120초 안에 전부 완주한다.

## 제외 범위

- 코스 크기, 카메라, 미니맵 UI 크기 변경
- 새 장애물 타입과 물리 엔진 변경
- 다중 맵, 맵 선택, 맵 편집기
- 새 스킬, 배속, 순위, 결과, 다시하기 변경
- 장애물을 빈틈없이 늘려 난이도만 높이는 변경

## 핵심 설계

### 1. 외곽 안전 프레임

기존 너비 `26`, 높이 `135`, viewport 높이 `24`를 유지한다. x=0과 x=26의 직선 외벽은 렌더링·이탈 방지용 안전 프레임이며 실제 주요 이동 경로를 결정하지 않는다.

### 2. 연속 지그재그 이동 벽

내부 이동 벽은 기존 `line` 장애물을 연결해 만든다. 새 `polyline` 타입은 추가하지 않는다.

왼쪽 연속 벽 꼭짓점:

```text
(0,0) → (4,12) → (2,24) → (5.5,32) → (2.5,43)
→ (2.5,57) → (3,62) → (3,76) → (1.5,86)
→ (4.5,96) → (2,106) → (0,108)
```

오른쪽 연속 벽 꼭짓점:

```text
(26,0) → (22,13) → (24,25) → (20.5,34) → (24,45)
→ (23.5,57) → (23,62) → (23,76) → (24.5,87)
→ (21.5,97) → (24,107) → (26,108)
```

- 두 벽은 y=0에서 외곽 모서리와 연결되어 시작 구슬이 벽 밖에 생성되지 않는다.
- 벽이 안쪽으로 들어오는 사선은 바깥쪽에서 낙하한 구슬을 중앙 통로로 미끄러지게 한다.
- y=62~76에서 실제 통로는 x=3~23의 직선 구간이다.
- y=108에서 양쪽 벽은 기존 결승 진입부 `(0,108)`, `(26,108)`와 연속적으로 이어진다.
- 선분 사이에 틈이 생기거나 교차하지 않아야 한다.

### 3. 상단 필수 충돌 구간

기존 램프와 상단 회전봉을 다음처럼 교체한다.

- 첫 램프: 왼쪽 벽의 `(4,12)`에서 `(17.1,17.1)`로 이어진다.
- 첫 회전봉: center `(19.5,19.5)`, length `7`, angle `0.15`, angularVelocity `+2.2`.
- 두 번째 램프: 오른쪽 벽의 `(24,25)`에서 `(10,30)`으로 이어진다.
- 두 번째 회전봉: center `(7.5,32)`, length `7.5`, angle `-0.2`, angularVelocity `-1.8`.

각 램프의 끝은 다음 회전봉의 회전 반경 안을 향한다. 두 회전봉은 서로 다른 높이와 방향에서 구슬 무리를 다시 섞는다. 회전봉이 벽 밖 비활성 영역에 일부 걸치는 것은 허용하되 외곽 x=0~26을 넘지 않는다.

### 4. 사각 범퍼 구간

기존 `box` 범퍼는 유지하되 새 내부 벽 안으로 재배치한다.

- y=34~40: 중심 x `6, 10, 14, 18`.
- y=41~47: 중심 x `4.5, 8, 12.5, 17, 21.5`.
- y=48~53: 중심 x `5, 9.5, 14, 18.5, 22`.
- y=54~58: 중심 x `6, 11, 16, 21`.
- 총 18개를 기준으로 하며 1×1 마름모와 너비 2~2.6의 짧은 판을 교차한다.
- restitution `0.7~0.8`의 반발 범퍼는 좌우에 고르게 6개만 둔다.
- circle은 기존처럼 3개 이하로 제한한다.
- 범퍼의 회전 외곽은 내부 이동 벽을 관통하지 않아야 한다.

### 5. y=68 회전봉 행

다섯 회전봉의 중심·속도는 유지하고 길이는 서로 겹치도록 늘린다.

```text
centers: (3,68), (8,68), (13,68), (18,68), (23,68)
length: 5.5
angularVelocity: +3.5, -3.5, +3.5, -3.5, +3.5
```

- 중심 간격은 5이고 길이는 5.5이므로 수평 상태에서 이웃 막대가 0.5씩 겹쳐 가로 빈틈이 없다.
- 왼쪽 회전봉은 x=0.25~5.75, 오른쪽 회전봉은 x=20.25~25.75을 훑는다.
- 실제 이동 벽은 x=3과 x=23이므로 첫·마지막 회전봉이 벽 밖까지 2.75씩 돌아 측면 우회를 막는다.
- 외곽 안전 프레임 x=0~26 안에는 남으므로 기존 validator 규칙을 바꾸지 않는다.

### 6. 하단 혼합 구간

하단 회전봉 2개의 크기와 속도는 유지하되 지그재그 벽 안에서 작동하도록 주변 범퍼만 재배치한다.

- `spinner:lower-left`: center `(7,83)`, length `6.5`, angularVelocity `+2`.
- `spinner:lower-right`: center `(19,99)`, length `7`, angularVelocity `-1.7`.
- y=80~108의 box·짧은 line은 해당 y에서 내부 벽보다 최소 0.35 안쪽에 둔다.
- 좌우 벽이 좁아지는 방향과 회전봉 위치를 교차해 한쪽의 긴 자유낙하 경로를 만들지 않는다.

### 7. 결승 반시계 게이트

깔때기와 세로 통로는 현재 수치를 유지한다.

- funnel: `(6.5,119) → (12.4,126)`, `(19.5,119) → (13.6,126)`.
- throat: x=12.4~13.6, 폭 `1.2`.
- chute: x=12.4~13.6, y=126~135.
- goal sensor: `(12.4,135) → (13.6,135)`.
- gate center: `(11.75,126)`.
- gate length: `3`.
- gate initial angle: `0`.
- gate angularVelocity: `-1.2`, 화면상 반시계 방향.

수평 상태의 게이트는 x=10.25~13.25를 훑어 폭 1.2 입구의 왼쪽을 가로막는다. 회전 중심이 입구 왼쪽에 있으므로 반시계 회전 시 막대 끝이 입구에서 구슬을 한 차례 걸친 뒤 통과 틈을 만든다. 중심을 깔때기 끝 y=126에 맞춰, 경사 위에서 구슬을 반복해서 밀어 올리지 않는다.

## 데이터 구조와 변경 범위

- `CourseDefinition`, `CourseObstacle`, `BoxObstacle`, `SpinnerObstacle`의 타입은 변경하지 않는다.
- 연속 벽은 `course.ts`의 `line` 배열로 표현한다.
- 좌표 중복을 줄이기 위해 파일 내부에만 `toLines(points)` helper를 둘 수 있다. 외부 API로 export하지 않는다.
- `Box2dPhysics`, `CanvasRenderer`, `Camera`, UI 컴포넌트는 실제 결함이 발견되지 않는 한 변경하지 않는다.
- 결승 게이트는 왼쪽 center x=11.75, y=126, length 3, 반시계 `-1.2` 조합을 사용한다.

## 안전 조건

- 내부 벽의 두 연속 선분은 같은 끝점을 정확히 공유한다.
- 같은 y에서 왼쪽 벽 x는 오른쪽 벽 x보다 작아야 한다.
- 구슬 지름 0.5를 고려해 각 굴곡지의 실제 통로 폭은 최소 1.2를 유지한다.
- 회전봉은 외곽 x=0~26 및 y=0~135 안에 있어야 한다. 내부 벽을 가로지르는 것은 의도된 설계로 허용한다.
- 상단 시작 구슬은 지그재그 벽 안에서 시작하고 벽 밖 폐쇄 공간에 고립되지 않아야 한다.
- 결승 게이트가 반시계로 돌아도 정체 해소 시스템이 영구 정체를 만들지 않아야 한다.

## 검증 설계

사용자가 요청한 최소 검증 원칙을 유지한다.

### 구조 검증

- 내부 왼쪽·오른쪽 벽이 명시된 꼭짓점을 끊김 없이 연결한다.
- y=68에서 활성 통로는 x=3~23이다.
- 중앙 회전봉은 길이 5.5로 이웃 막대와 0.5씩 겹치며, 첫·마지막 막대가 내부 벽을 2.75씩 넘는다.
- 상단 램프 끝점은 다음 회전봉의 회전 영역 안에 있다.
- 결승 게이트는 center (11.75,126), length 3, angularVelocity -1.2이다.

### 대표 물리 검증

고정 시드 1의 100구슬 레이스를 한 번만 실행하며 아래를 한 번에 측정한다.

- 상단 각 회전봉의 충돌 영역을 지나는 고유 구슬이 각각 10개 이상이다.
- y=68 회전봉 행의 충돌 영역을 지나는 고유 구슬이 40개 이상이다.
- 결승 게이트 반경 1 안에서 300ms 이상 머문 구슬이 1개 이상이어야 한다.
- 그러면서 100개 모두 120초 안에 유효한 골인 센서를 통과한다.
- 코스 외 탈출, NaN, 영구 정체가 없어야 한다.

충돌 영역은 테스트 내에서 현재 spinner snapshot의 선분과 구슬 중심 사이의 최단 거리를 구해 `구슬 반경 + 0.1` 이하인 경우로 정의한다. 제품 API에 충돌 카운터를 추가하지 않는다.

### 실행 예산

1. 구조 타겟 테스트 RED/GREEN을 각 1회 실행한다.
2. 고정 시드 100구슬 물리 검증을 최종 좌표에서 1회 실행한다.
3. 전체 단위 테스트를 종료 시점에 1회 실행한다.
4. production build를 1회 실행한다.
5. 다중 시드, 복수 브라우저·viewport, `repeat-each`, 성능 반복 측정은 실행하지 않는다.
6. 구체적 실패가 발생했을 때만 실패 구간을 기록하는 진단 1회를 추가한다.

## 완료 기준

- 미니맵에서 외곽 프레임 안의 지그재그 실제 이동 통로가 분명하게 보인다.
- 상단 회전봉 2개가 장식이 아니라 다수의 구슬을 직접 섞는다.
- y=68의 막대 사이는 통과 가능하지만 양쪽 밖으로 우회할 수 없다.
- 결승 막대가 화면상 반시계로 회전하고, 구슬이 한 번 걸린 뒤 통과하는 모습이 발생한다.
- 대표 100구슬은 영구 정체 없이 완주한다.
- 기존 참가자 설정, 스킬, 배속, 순위, 결과, 다시하기 흐름은 변경되지 않는다.
