# NotMe MVP 설계

## 1. 목적

NotMe는 모임에서 한 대의 휴대폰을 돌려 사용하며 참가자나 결과를 정하는 벌칙·추첨 게임 PWA다. 첫 MVP는 스톱워치, 사다리 타기, 마블 룰렛 세 게임을 제공한다. PC에서도 사용할 수 있지만 모바일 세로 화면과 한 손 조작을 우선한다.

## 2. 제품 원칙

- 홈에서 게임을 먼저 선택하고 참가자는 각 게임 안에서 해당 판마다 입력한다.
- 앱 전체에서 공유하는 참가자 명단, 회원가입, 서버, 데이터베이스는 두지 않는다.
- `초기화`는 현재 게임 화면에 머물면서 새 판을 준비한다.
- `홈으로`는 진행 중일 때 확인을 받은 뒤 현재 판의 참가자와 진행 상태를 모두 삭제한다.
- 새로고침이나 실수로 앱을 닫은 경우에만 현재 판을 기기 저장소에서 복구한다. 정상적으로 초기화하거나 홈으로 이동하면 복구 데이터도 삭제한다.
- 첫 접속에서 필요한 파일을 받은 뒤에는 오프라인에서도 핵심 게임을 실행할 수 있어야 한다.

## 3. 범위

### 포함

- 모바일 우선 반응형 PWA
- 웜 다크 테마의 미니멀 목록형 홈
- 스톱워치 게임
- 사다리 타기
- 긴 세로 코스의 마블 룰렛
- 홈 화면 설치용 Manifest와 오프라인 캐시
- GitHub Pages를 우선 대상으로 하는 정적 배포 구성

### 제외

- 온라인 방, 실시간 멀티플레이
- 회원가입, 계정, 전적 저장
- 서버 API와 데이터베이스
- 푸시 알림과 결과 공유
- 마블 룰렛의 여러 맵, 화면 녹화, 광고, 커스텀 당첨 순위, 다크·라이트 테마 전환

## 4. 기술 구조

- React, TypeScript, Vite로 정적 클라이언트 앱을 만든다.
- 홈과 세 게임은 `/`, `/stopwatch`, `/ladder`, `/marble` 경로로 분리한다.
- 공통 앱 셸은 상단의 홈 이동, 초기화, 진행 중 이탈 확인과 PWA 업데이트 안내만 담당한다.
- 각 게임은 자체 상태와 규칙 모듈을 가지며 다른 게임의 참가자나 결과를 참조하지 않는다.
- 일반 UI는 React로 렌더링한다. 마블 레이스의 물리 계산과 Canvas 렌더링은 React 생명주기와 분리된 엔진 모듈로 둔다.
- 현재 판 복구 데이터는 게임별 버전이 포함된 기기 저장소 키 하나에 기록한다. 버전이 맞지 않거나 데이터가 손상되면 해당 데이터만 폐기하고 새 판으로 연다.
- 배포 경로가 `/NotMe/`인 GitHub Pages에서도 Manifest, 아이콘, 서비스 워커와 라우팅이 정상 동작하도록 Vite 기본 경로를 설정한다.

예상 소스 경계는 다음과 같다.

```text
src/
  app/                 라우팅, 공통 앱 셸, 전역 스타일
  features/stopwatch/  참가자 순서, 측정, 점수, 동점 재대결
  features/ladder/     설정, 사다리 생성, 경로 계산, 결과 공개
  features/marble/     설정 UI와 룰렛 엔진 연결
  features/marble/engine/
                       Box2D, 코스, 카메라, 미니맵, 순위, 스킬, 배속
  shared/              공통 버튼, 입력, 확인창, 판 복구 유틸리티
```

## 5. 공통 화면과 시각 언어

- 홈은 `NOT ME` 브랜드, 짧은 설명, 세 게임의 목록으로 구성한다.
- 기본 배경은 짙은 갈색, 표면은 한 단계 밝은 갈색, 주요 행동은 주황 계열 강조색을 쓴다.
- 게임별 보조색은 다르게 사용할 수 있지만 공통 상단 바와 주요 버튼 위치는 유지한다.
- 모든 주요 터치 영역은 최소 44×44 CSS 픽셀로 만들고 기기의 안전 영역을 반영한다.
- 모바일은 세로 화면을 우선한다. 데스크톱에서는 콘텐츠 최대 너비를 제한해 모바일 조작 구조를 유지한다.
- 진행 중 홈 이동에는 확인창을 표시한다. 설정만 입력한 상태나 결과 화면에서도 홈 이동 시 해당 판은 삭제한다.

## 6. 스톱워치 게임

### 설정

- 두 명 이상의 참가자 이름을 입력한다.
- 참가자는 입력된 순서대로 진행한다.

### 진행

1. 현재 참가자의 이름과 측정 차수를 크게 표시한다.
2. 참가자는 첫 번째 스톱워치를 시작하고 멈춘다.
3. 화면에 1/100초까지 표시된 기록의 마지막 숫자를 첫 번째 값으로 저장한다.
4. 같은 방식으로 두 번째 값을 측정한다.
5. 두 마지막 숫자의 곱을 참가자의 점수로 저장한다.
6. 모든 참가자가 끝날 때까지 기기를 다음 사람에게 넘긴다.

스톱워치는 화면 갱신 주기와 별개로 단조 증가 시계인 `performance.now()`를 기준으로 계산한다. 탭이나 PWA가 백그라운드로 이동하면 진행 중인 측정은 무효화하고 해당 측정부터 다시 시작한다.

### 결과

- 가장 낮은 점수를 받은 참가자가 선택된다.
- 최저 점수 동점자가 두 명 이상이면 동점자만 새 라운드에서 다시 두 번 측정한다.
- 한 명이 남을 때까지 같은 규칙으로 재대결한다.
- 결과 화면에는 참가자별 두 숫자, 곱, 최종 선택자를 표시한다.

## 7. 사다리 타기

### 설정

- 사다리 수는 최소 2개이며 수에 맞춰 참가자 이름과 결과 입력 칸이 함께 늘어난다.
- 결과는 두 방식으로 준비한다.
  - 기본 채우기: `벌칙` 한 칸과 나머지 `통과`
  - 직접 입력: 모든 결과를 자유롭게 작성
- 참가자 이름과 결과 수가 사다리 수와 같고 모든 칸이 채워져야 시작할 수 있다.
- `섞기`를 누르면 참가자와 결과의 표시 순서를 각각 무작위로 바꾼다. 누르지 않으면 입력 순서를 유지한다.

### 생성과 진행

- 시작 시 사다리 구조와 모든 경로 결과를 한 번 생성해 고정한다.
- 각 가로선은 인접한 두 세로선만 연결하며 같은 높이에서 겹치지 않는다.
- 참가자나 결과가 화면 너비를 넘으면 사다리 영역만 가로로 이동할 수 있게 한다.
- 참가자 이름을 누르면 해당 경로를 애니메이션으로 따라가 결과를 공개한다.
- `전체 결과 보기`로 남은 경로를 한 번에 공개할 수 있다.
- 애니메이션은 이미 고정된 경로를 표현할 뿐 결과를 다시 계산하지 않는다.

## 8. 마블 룰렛

### 참고와 라이선스

- `lazygyu/roulette`의 MIT 라이선스 코드를 참고하며, 사용하거나 수정한 코드에는 원 저작권 고지와 라이선스를 유지한다.
- Box2D 연동, 코스 데이터 구조, 카메라 추적, 미니맵, 배속, 순위 계산과 스킬 시스템을 선별적으로 이식할 수 있다.
- 광고, 화면 녹화, 외부 상점, 여러 맵과 기존 사이트 UI는 가져오지 않는다.
- React 설정 화면과 웜 다크 시각 디자인은 NotMe용으로 새로 작성한다.

### 설정

- 참가자는 원하는 만큼 추가할 수 있다.
- 참가자마다 같은 이름의 구슬 개수를 `1~100` 사이에서 설정할 수 있다.
- 한 판의 모든 구슬 합계는 최대 100개다. 한도는 설정 상수 하나로 관리해 성능 검증 후 바꿀 수 있게 한다.
- 참가자별 물리 무게나 별도 확률 가중치 설정은 제공하지 않는다.
- 구슬의 크기, 질량과 기본 물리 속성은 모두 같다.
- 스킬을 활성화하면 모든 구슬에 같은 발동 조건과 확률을 적용한다.
- 당첨 순위는 `첫 번째`와 `마지막` 중 하나를 고른다.
- 시작 전에 `섞기`로 모든 구슬의 시작 위치를 무작위 배치한다. 시작할 때도 마지막으로 확정된 배치 순서를 사용한다.

참가자별 구슬 수가 다르면 당첨 가능성도 달라지는 것은 의도된 기능이다. 별도의 무게 설정은 없으며 확률 차이는 구슬 개수로만 만든다.

### 코스와 진행

- MVP는 하나의 긴 세로 코스만 제공한다.
- 코스는 화면 약 다섯 높이 분량을 기준으로 경사로, 핀, 회전체, 갈림길과 최종 골인 구간을 배치한다.
- 시작하면 설정 패널을 숨기고 Canvas가 게임 화면 대부분을 차지한다.
- 카메라는 당첨 판정에 필요한 구슬 무리를 중심으로 코스를 따라 내려간다.
- 미니맵에는 전체 코스, 구슬 분포와 현재 카메라 영역을 표시한다.
- 현재 도착 예상 순위 또는 도착 순위를 화면 위에 계속 표시한다.
- 화면을 누르고 있는 동안 4배속으로 진행하고 손을 떼거나 포인터가 취소되면 즉시 정상 속도로 돌아간다.
- 스킬은 모든 구슬에 같은 확률로 적용되는 충돌 효과로 한정한다. 스킬 사용 여부는 시작 전에 선택한다.

### 결과

- 골인선을 처음 통과한 순간 각 구슬의 순위를 한 번만 기록한다.
- `첫 번째`는 가장 먼저 도착한 구슬의 참가자를, `마지막`은 마지막으로 도착한 구슬의 참가자를 선택한다.
- 같은 참가자의 여러 구슬은 각각 독립적으로 순위에 포함된다.
- 선택된 구슬, 참가자 이름과 전체 도착 순위를 결과에 표시한다.

## 9. 데이터 수명과 화면 전환

```text
홈 → 게임 설정 → 게임 진행 → 결과
 ↑                               │
 └──── 홈 이동 확인 후 판 삭제 ──┘
```

- 게임 상태는 현재 경로의 기능 모듈만 소유한다.
- 설정이나 진행 상태가 바뀔 때 현재 판 복구 데이터를 갱신한다.
- `초기화`는 해당 게임의 참가자, 설정, 진행 결과와 복구 데이터를 지운 뒤 같은 게임의 초기 설정 화면으로 이동한다.
- `홈으로`는 진행 상태를 지운 뒤 홈으로 이동한다.
- 다른 게임으로 상태가 전달되지 않는다.

## 10. 입력 검증과 오류 처리

- 모든 게임은 참가자가 두 명 이상이어야 시작할 수 있다.
- 이름 앞뒤 공백은 제거하고 빈 이름은 저장하지 않는다.
- 잘못된 값은 입력 칸 가까이에 이유와 해결 방법을 표시한다.
- 사다리는 참가자와 결과의 개수가 맞지 않으면 시작하지 않는다.
- 룰렛은 참가자별 구슬 수와 총 구슬 수를 즉시 다시 계산한다. 100개를 넘으면 현재 합계와 줄여야 할 개수를 안내한다.
- Box2D 또는 코스 리소스 로딩에 실패하면 빈 게임판을 시작하지 않고 재시도와 홈 이동을 제공한다.
- 룰렛 진행 중 구슬이 일정 시간 움직이지 않으면 참고 엔진의 안전한 흔들기 처리를 사용해 정체를 해소한다.
- 서비스 워커 업데이트가 준비되면 판을 진행 중이지 않을 때만 새 버전 적용 버튼을 보여준다.

## 11. 테스트 전략

### 단위 테스트

- 스톱워치의 1/100초 마지막 숫자 추출, 두 값의 곱, 최저 점수와 동점자 선별
- 사다리 생성 규칙, 모든 시작점이 정확히 하나의 결과에 연결되는지, 고정된 경로의 재현성
- 룰렛 참가자별 구슬 복제, 총 100개 제한, 시작 위치 섞기, 첫 번째·마지막 판정
- 현재 판 저장, 손상 데이터 폐기, 초기화와 홈 이동 시 삭제

### 통합·브라우저 테스트

- 홈에서 각 게임으로 이동하고 홈 복귀 시 상태가 초기화되는지 확인
- 진행 중 홈 이동 확인창과 취소·확인 동작 확인
- 스톱워치 백그라운드 전환 시 현재 측정 무효화 확인
- 사다리 개별 공개와 전체 공개 확인
- 룰렛 포인터 누름·해제·취소에 따른 배속 복귀 확인
- 서비스 워커 설치 후 오프라인에서 홈과 세 게임이 열리는지 확인

### 물리·반응형 검증

- 룰렛은 정해진 난수와 단순 코스로 순위 기록을 검증하되 픽셀 단위 궤적을 테스트하지 않는다.
- 실제 긴 코스는 100개 구슬로 모바일 성능과 완주 여부를 반복 측정한다.
- 작은 모바일, 일반 모바일, 데스크톱 화면에서 입력 가림, 안전 영역, 가로 넘침을 확인한다.

## 12. 완료 기준

- 세 게임이 모바일과 데스크톱에서 설정부터 결과까지 완료된다.
- 게임별 초기화와 홈 이동 시 상태 삭제가 합의한 방식으로 동작한다.
- 스톱워치 동점 재대결, 사다리 일대일 연결, 룰렛 첫 번째·마지막 판정 테스트가 통과한다.
- 룰렛 100개 구슬이 긴 코스를 완주하고 배속 해제 후 정상 속도로 복귀한다.
- 설치 가능한 PWA로 빌드되며 첫 접속 이후 오프라인에서 세 게임을 열 수 있다.
- 참고한 MIT 코드의 저작권 고지와 라이선스가 배포 결과와 저장소에 포함된다.
