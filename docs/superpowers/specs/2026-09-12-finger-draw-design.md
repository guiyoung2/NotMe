# 손가락 추첨 게임 설계

## 목적과 범위

NotMe에 한 대의 휴대폰을 여러 사람이 동시에 누르고 한 명을 무작위로 선택하는 `손가락 추첨` 게임을 추가한다. 별도 참가자 입력 없이 바로 사용할 수 있는 오프라인 PWA 게임이며, 선택된 사람의 의미는 당첨·벌칙 어느 쪽에도 사용할 수 있도록 중립적으로 표현한다.

이번 MVP는 다음 범위만 포함한다.

- 동시에 인식된 손가락이 2개 이상이면 3초 카운트다운을 시작한다.
- 최대 10개의 손가락을 참가자로 인정한다.
- 카운트다운 중 참가자가 추가되거나 제거되면 3초부터 다시 시작한다.
- 손가락 이동은 같은 참가자의 위치 변경으로 처리한다.
- 카운트다운이 끝나면 한 명을 무작위로 선택한다.
- 결과 화면의 `다시 하기` 버튼으로 대기 상태로 돌아간다.

이름 입력, 참가 인원 표시, 여러 명 동시 선택, 효과음, 사용자 설정, 결과 저장은 포함하지 않는다.

## 화면 구성

게임 경로는 `/finger`를 사용하고 홈에 `손가락 추첨` 항목을 추가한다. 기존 `GameShell`을 사용하되 이 게임에서는 우측 상단 `초기화` 버튼을 숨긴다. 설정이나 저장할 진행 정보가 없으므로 홈 버튼을 누를 때 종료 확인창도 표시하지 않는다.

게임 본문은 휴대폰에서 가능한 넓은 터치 영역을 제공한다. 화면 상태별 표현은 다음과 같다.

1. **대기:** `화면에 손가락을 올려주세요`를 작은 화면에서도 한 줄로 표시하고, 아래에 `2명 이상이면 자동으로 시작해요`를 표시한다.
2. **첫 카운트다운:** 각 손가락 위치에 서로 다른 색의 원을 표시한다. 중앙에 남은 숫자와 `그대로 유지하세요`를 표시한다. 원은 천천히 커졌다 작아지며 카운트가 진행 중임을 알린다.
3. **참가자 변경 후 카운트다운:** 숫자 아래에 `다시 시작해요`, 그 아래 작은 글씨로 `손가락을 유지하세요`를 표시한다.
4. **결과:** 선택된 원은 크게 강조하고 나머지 원은 흐리게 표시한다. 중앙에 `선택됐어요!`를 표시하고 하단에 `다시 하기` 버튼을 둔다.

원 안에는 번호나 이름을 넣지 않는다. 색상은 한 판 안에서 참가자를 구별하는 용도로만 사용하며, 동일한 `pointerId`에는 이동 후에도 같은 색을 유지한다. 결과는 강조 크기와 명암도 함께 사용해 색상만으로 전달하지 않는다. `prefers-reduced-motion` 환경에서는 크기 애니메이션을 비활성화한다.

## 상태와 데이터 흐름

게임 규칙은 React 화면 코드와 분리된 순수 상태 전이 모듈로 구현한다.

- `waiting`: 인식된 참가자가 0명 또는 1명인 상태
- `countdown`: 참가자가 2명 이상이며 3초 타이머가 진행 중인 상태
- `result`: 선택된 참가자와 선택 시점의 모든 원 위치를 고정해 보여주는 상태

각 참가자는 브라우저가 제공하는 `pointerId`, 현재 `x/y` 좌표, 배정된 색을 가진다. 상태에는 현재 참가자 집합, 카운트다운 시작 시각, 카운트다운 버전, 시작 사유와 선택된 `pointerId`를 저장한다. 시작 사유는 최초 시작과 참가자 변경 후 재시작 안내를 구분한다.

입력은 다음 규칙으로 처리한다.

- `pointerdown`: 결과 상태가 아니고 참가자가 10명 미만이면 새 참가자를 추가하고 포인터를 터치 영역에 캡처한다.
- `pointermove`: 등록된 `pointerId`의 좌표와 색상 정체성을 유지한 채 위치만 갱신한다.
- `pointerup`, `pointercancel`, 예기치 않은 포인터 캡처 상실: 해당 참가자를 제거한다.
- 참가자 집합이 변경된 뒤 2명 이상이면 카운트다운 시작 시각과 버전을 갱신한다. 1명 이하이면 `waiting`으로 전환한다.
- 이미 10명이 등록된 상태에서 들어온 추가 포인터는 참가자로 등록하지 않으며 카운트다운도 재시작하지 않는다.
- `result`에서는 포인터 추가·이동·제거 이벤트를 게임 상태에 반영하지 않는다.
- `다시 하기`는 참가자, 위치, 결과와 타이머를 모두 지우고 `waiting`으로 전환한다.

카운트다운 효과는 현재 시작 시각을 기준으로 화면에 남은 정수를 계산한다. 실제 완료는 하나의 타이머가 담당하며, 참가자 변경 시 이전 타이머를 정리한다. 완료 이벤트에는 카운트다운 버전을 포함해 이미 취소된 타이머가 늦게 실행되더라도 결과를 만들지 못하게 한다.

카운트다운 중 브라우저 탭이 숨겨지면 공정하지 않은 백그라운드 완료를 막기 위해 게임을 `waiting`으로 초기화한다. 이미 공개된 `result` 상태는 탭 가시성 변경만으로 지우지 않는다.

## 무작위 선택

카운트다운이 끝나는 순간의 등록된 `pointerId` 목록에서 하나를 선택한다. 브라우저의 `crypto.getRandomValues()`를 사용하고, 선택 함수에는 난수 공급자를 주입할 수 있게 해 단위 테스트에서 결과를 결정적으로 검증한다.

선택 완료 후 참가자 위치를 결과 상태에 고정한다. 사용자가 손가락을 떼더라도 결과 원은 유지되며, 다음 판은 반드시 `다시 하기` 버튼으로 시작한다.

## 컴포넌트와 변경 파일

- `src/features/finger/fingerDrawMachine.ts`: 상태 타입, 순수 전이 규칙, 무작위 선택 보조 함수
- `src/features/finger/fingerDrawMachine.test.ts`: 인원 변경, 제한, 이동, 오래된 타이머와 선택 규칙 단위 테스트
- `src/features/finger/FingerDrawPage.tsx`: Pointer Events 연결, 타이머 생명주기, 접근성 안내와 화면 렌더링
- `src/features/finger/FingerDrawPage.test.tsx`: 사용자 흐름과 가상 타이머 기반 페이지 테스트
- `src/features/finger/fingerDraw.css`: 전체 터치 영역, 원 위치·색상·상태 애니메이션과 반응형 스타일
- `src/app/GameShell.tsx`: 기존 동작을 유지하는 선택적 초기화 버튼 표시 속성 추가
- `src/app/App.tsx`, `src/app/HomePage.tsx`: `/finger` 라우트와 홈 항목 추가
- 기존 앱 테스트 및 `e2e/finger.spec.ts`: 새 라우트, 홈 이동, 핵심 게임 흐름 검증
- `README.md`: 게임 사용법과 전체 검증 대상에 손가락 추첨 추가

다른 게임의 상태, 저장 방식과 스타일은 변경하지 않는다. 손가락 추첨은 일시적인 동시 입력만 다루므로 `draftStorage`에 저장하지 않는다.

## 오류 및 기기 제약 처리

터치 영역에는 `touch-action: none`, 텍스트 선택 방지와 오버스크롤 억제를 적용해 게임 중 브라우저 제스처 충돌을 줄인다. 상단 홈 영역과 결과의 `다시 하기` 버튼은 일반 버튼 동작을 유지한다.

앱은 최대 10개의 Pointer Event를 처리하지만 실제 동시 터치 인식 수는 기기와 브라우저 하드웨어 제한을 따른다. 지원하지 않는 추가 접촉은 앱이 감지할 수 없으므로 별도의 오류로 표시하지 않는다. 마우스로는 기능을 확인할 수 있지만 실제 게임 안내는 손가락 표현을 유지한다.

## 검증 기준

자동 테스트는 다음을 확인한다.

- 0~1명에서는 대기하고 2명이 되면 3초 카운트다운을 시작한다.
- 최초 카운트다운과 참가자 변경 후 안내 문구가 구분된다.
- 참가자 추가 또는 제거마다 카운트다운이 3초로 재설정된다.
- 2명에서 1명으로 줄면 대기로 돌아간다.
- 이동한 포인터의 ID와 색은 유지되고 좌표만 변경된다.
- 10명까지 등록되며 11번째 포인터는 상태와 타이머에 영향을 주지 않는다.
- 취소된 이전 타이머는 결과를 만들지 않는다.
- 완료 시 등록 참가자 중 정확히 한 명만 선택된다.
- 결과에서 포인터 이벤트를 무시하고 `다시 하기`로 초기화한다.
- 홈에 게임 링크가 보이고 `/finger` 직접 진입과 PWA 서비스 워커 등록이 유지된다.
- 320px 모바일 너비에서 첫 안내가 한 줄이며 주요 UI가 잘리지 않는다.

전체 단위 테스트, TypeScript 검사, 프로덕션 빌드와 기존 E2E를 통과해야 한다. 합성 Pointer Event 테스트와 별도로 실제 멀티터치 기기에서 2명, 참가자 추가·제거, 손가락 이동과 가능한 범위의 다중 터치를 수동 확인한다.
