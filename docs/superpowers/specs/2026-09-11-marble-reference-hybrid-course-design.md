# 마블 룰렛 참고형 혼합 코스 설계

## 배경

현재 마블 코스는 정적인 원형 핀이 많고 회전봉이 한 높이에 몰려 있다. 장애물 수는 늘었지만 구간마다 다른 상호작용이 일어나지 않아 단조롭게 보인다. 마지막 깔때기는 세로 길이에 비해 가로 수렴 폭이 작아 가파르고 길어 보이며, 골인 회전봉도 입구를 명확하게 가로막지 못한다.

이번 변경은 `lazygyu/roulette`의 첫 번째 맵에서 효과적인 구조를 참고하되, 사용자가 요청한 분산 회전봉을 결합한 단일 코스로 다시 구성한다. 여러 맵, 맵 선택, 편집 기능은 추가하지 않는다.

## 목표

- 큰 다이아몬드 구조를 사용하지 않는다.
- 원형 핀 위주의 규칙적인 격자 구성을 없앤다.
- 작은 사각·마름모 범퍼와 짧은 발판으로 진로 변화를 만든다.
- 회전봉을 코스 상단부터 골인 직전까지 분산한다.
- 참고 맵의 가로 회전봉 묶음은 별도 핵심 구간으로 유지한다.
- 마지막 입구 바로 앞의 긴 회전봉이 구슬을 실제로 막았다가 통과시킨다.
- 마지막 깔때기는 짧고 완만하며, 통과 후 좁은 세로 통로 끝에서만 골인한다.
- 한 대의 모바일 화면에서도 장애물 종류와 구간 변화가 미니맵으로 구분된다.

## 제외 범위

- 다중 맵과 맵 선택 UI
- 맵 편집기와 사용자 지정 장애물
- 새로운 스킬, 배속, 카메라, 순위 UI 변경
- 별도 애니메이션 엔진이나 물리 라이브러리 교체
- 성능 벤치마크 반복 실행과 전체 E2E 반복 실행

## 장애물 모델

기존 `line`, `circle`, `spinner`에 정적 `box`를 추가한다.

```ts
type BoxObstacle = {
  kind: 'box';
  center: CoursePoint;
  width: number;
  height: number;
  angle: number;
  restitution: number;
};
```

- `width`, `height`는 양수여야 한다.
- `angle`은 라디안 단위의 유한값이다.
- `restitution`은 `0`부터 `1` 사이 값이다.
- 회전된 실제 외곽 범위까지 코스 안에 있어야 한다.
- Box2D에서는 정적 polygon box로 생성한다.
- Canvas에서는 같은 중심·크기·각도로 회전한 사각형을 그린다.
- 일반 범퍼는 웜 다크 코스 선색을 사용하고, 반발력이 있는 범퍼는 기존 주황색 accent로 구분한다.

`circle` 타입은 호환을 위해 유지하지만 새 코스에서는 3~5개만 사용한다. 기존 `spinner` 타입과 동적 snapshot 인터페이스는 바꾸지 않는다.

## 코스 구성

코스 크기는 너비 `26`, 높이 `135`, 기본 viewport 높이 `24`를 유지한다.

### 1. 상단 분산 구간: y 0~30

- 좌우에서 교차하는 짧은 경사 발판을 배치한다.
- 길이 약 `5~7`의 회전봉 2개를 서로 다른 높이와 좌우 위치에 둔다.
- 두 회전봉은 반대 방향으로 회전한다.
- 시작 중앙에서 그대로 자유낙하하는 세로 통로를 만들지 않는다.

### 2. 사각 범퍼 구간: y 30~58

- 작은 마름모 범퍼와 얇은 직사각형 발판을 불규칙하게 배치한다.
- 같은 x 간격의 원형 격자를 사용하지 않는다.
- 일부 마름모는 restitution을 높여 구슬이 짧게 위로 튀게 한다.
- 중앙과 양쪽 경로가 번갈아 열리도록 배치해 구슬 무리가 한 줄로 고정되지 않게 한다.

### 3. 가로 회전봉 구간: y 60~76

- 참고 맵처럼 짧은 회전봉 5개를 한 높이에 나란히 둔다.
- 회전 방향은 `+ - + - +`로 교차한다.
- 회전봉 사이 간격은 구슬 한 개가 빠질 수 있지만 무리가 한꺼번에 통과하기에는 좁게 둔다.
- 이 구간에서는 구슬이 잠시 막히거나 위로 튀어 순서가 다시 섞이는 것이 정상 동작이다.

### 4. 혼합 낙하 구간: y 76~112

- 긴 회전봉 2개를 서로 다른 높이·좌우 위치·회전 방향으로 배치한다.
- 짧은 경사 발판과 사각 범퍼를 함께 사용한다.
- 큰 폐쇄형 다이아몬드나 긴 `ㅅ`형 구조를 만들지 않는다.
- 어느 한쪽에 긴 빈 낙하 통로가 생기지 않도록 좌우 장애물을 교차 배치한다.

### 5. 골인 병목: y 112~135

- 먼저 내부 유도벽으로 접근 폭을 약 `13`까지 줄인다.
- 최종 깔때기는 높이 약 `7`, 좌우 수렴 폭 약 `6`으로 만들어 화면상 약 45~50도 경사가 되게 한다.
- 깔때기 끝의 입구 폭은 `1.2`로 한다.
- 입구 바로 앞에 길이 `5.5`, 각속도 약 `-1.2`의 회전봉을 둔다.
- 회전봉이 수평일 때 입구 전체를 막고, 기울거나 수직에 가까워질 때 한쪽 틈이 열린다.
- 회전 중심은 입구 중앙보다 왼쪽에 두어 수직 상태에서 오른쪽 통과 폭을 확보한다.
- 입구 아래에는 폭 `1.2`, 길이 약 `9`의 세로 통로를 둔다.
- 골인 센서는 세로 통로 맨 아래에만 둔다.
- 기존 3초 정체 해소를 유지해 영구 정체를 방지한다.

## 회전봉 분포

총 10개를 사용한다.

- 상단 분산용 2개
- 가로 혼합용 5개
- 하단 혼합용 2개
- 골인 게이트 1개

길이·위치·속도를 구간별로 다르게 하되, 무작위로 움직이지 않는다. 동일 설정으로 다시 시작할 때 물리 시드가 같으면 기존 결정적 동작을 유지한다.

## 데이터와 렌더링 흐름

1. `course.ts`가 line, circle, box, spinner 장애물을 제공한다.
2. `Box2dPhysics.createCourse`가 box를 정적 body로 생성하고 restitution을 fixture에 설정한다.
3. `CanvasRenderer`가 정적 box를 course 또는 accent 색으로 회전 렌더링한다.
4. spinner는 기존처럼 Box2D snapshot의 현재 angle로 렌더링한다.
5. 골인 판정은 기존 엔진 로직을 유지하고 새 `goalSensor` 좌표만 사용한다.

## 오류와 안전 조건

- 유효하지 않은 box 크기, 각도, restitution, 코스 밖 회전 외곽을 validator가 거부한다.
- 회전봉과 벽이 초기 상태에서 겹쳐 통로를 영구 봉쇄하지 않게 한다.
- 구슬 반경 `0.25`를 고려해 세로 통로의 실제 판정 가능 폭을 남긴다.
- 좁은 입구 밖으로 골인선을 교차하면 기존처럼 시작 위치로 복귀한다.

## 검증 범위와 실행 예산

사용자가 요청한 최소 검증 원칙을 적용한다.

### 실행할 검증

1. TDD에 필요한 box 타입·물리·렌더·validator 대상 테스트를 RED/GREEN 각각 필요한 횟수만 실행한다.
2. 코스 구조 대상 테스트를 실행해 회전봉 분포, 깔때기 경사, 입구 폭과 게이트 길이를 확인한다.
3. 실제 Box2D 100구슬 완주 검사는 대표 고정 시드 1개로 한 번만 실행한다.
4. 구현 종료 시 전체 단위 테스트를 한 번 실행한다.
5. TypeScript와 production build를 한 번 실행한다.
6. 모바일 390×844에서 한 레이스만 실행해 상단, 가로 회전봉, 하단, 골인 게이트를 필요한 최소 캡처로 직접 확인한다.

### 실행하지 않을 검증

- `repeat-each` 반복
- 여러 브라우저·여러 viewport의 동일 레이스 반복
- 5개 이상의 물리 시드 반복
- 이미 단위 테스트가 담당하는 스킬·순위·PWA 전체 E2E 재실행
- 성능 수치 재측정 및 프레임 p95 반복
- 코드 변경이 없는 상태에서 같은 테스트 재실행

실제 완주 실패, 간헐 오류, 프레임 정지처럼 구체적인 문제가 관찰된 경우에만 원인을 확인하는 최소 추가 검증을 허용한다. 추가 검증을 할 때는 무엇이 실패했고 왜 필요한지 먼저 알린다.

## 완료 기준

- 큰 다이아몬드와 원형 격자 위주의 기존 코스가 보이지 않는다.
- 미니맵만 보아도 상단, 범퍼, 가로 회전봉, 혼합 구간, 골인 병목이 구분된다.
- 회전봉이 한 높이에만 몰리지 않는다.
- 마지막 긴 회전봉이 좁은 입구를 실제로 가로막으며 구슬이 회전 각도에 따라 통과한다.
- 마지막 깔때기가 이전보다 짧고 완만하게 보인다.
- 대표 100구슬 레이스가 영구 정체 없이 완료된다.
- 기존 참가자 설정, 스킬, 배속, 결과 화면 동작을 변경하지 않는다.
